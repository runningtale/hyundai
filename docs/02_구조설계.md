## 1. 전체 그림

```
 [Pleos NaviHelper] --목적지, 남은 시간, 터널 예고-->  navi/NaviGateway  --+
                                                                         |  DriveEvent
 [Pleos Vehicle]   --기어, 착석, 와이퍼, 전조등-->     vehicle/VehicleGateway --+
                                                                         v
                                                       playback/StoryDirector  (판단의 중심)
                                                        |        |         |
                                   이야기 요청          |        | 효과    | 낭독
                                                        v        v         v
                                      story/StoryGenerator  vehicle/EffectController  playback/Narrator
                                        |                        |                        |
                                        v                        v                        v
                               외부 LLM API (키 없으면 데모)   Pleos Vehicle(독서등, 풍량)   Pleos TextToSpeech

 [차 미디어 화면, 핸들 버튼] --재생/일시정지/다음--> playback/StoryMediaService --> StoryDirector
```

- **StoryDirector가 유일한 판단 주체.** 언제 다음 장을 만들지, 끼어들기를 언제 넣을지, 효과를 언제 낼지는 모두 여기서 정함
- 다른 모듈은 자기 일만 함: Gateway는 사건을 알리고, Generator는 문장을 만들고, EffectController는 안전 규칙 안에서 차를 바꾸고, Narrator는 읽음
- LLM은 문장과 효과 태그만 만듦. 차량 제어 여부는 EffectController 규칙이 최종 결정

## 3. 실시간 생성 흐름

### 3-1. 출발 (1층)
1. 부모가 미디어 화면이나 핸들에서 재생을 누름 → `StoryMediaService` → `StoryDirector.start()`
2. Director가 고정 도입부 문장을 바로 낭독 시작 (대기 시간 숨기기)
3. 동시에 `TripState`(목적지, 남은 시간, 시간대, 비)로 `StoryGenerator.createSkeleton()` 호출 → 뼈대 + 1장
4. 도입부가 끝나면 1장 낭독

### 3-2. 주행 중 (2층)
- Director는 남은 낭독 시간을 추정 (문장 수 × 평균 낭독 시간)
- 지금 장이 약 90초 남으면 `StoryGenerator.nextChapter()` 호출. 그 순간의 `TripState`를 넣음
- 남은 도착 시간이 3분 이하이면 `isFinal = true`로 결말 장을 요청
- 다음 장이 늦게 오면 범용 이음 문장으로 시간을 벌고, 30초 넘게 실패하면 기본 이야기의 다음 장으로 대체

### 3-3. 도로 이벤트 (3층)
| 이벤트 | 예고 | 처리 |
|---|---|---|
| 터널, 요금소, 휴게소 | 내비가 남은 거리로 알려 줌 | 약 1km 전에 `interlude()` 미리 생성 → 진입(거리 약 50m 이하) 순간 지금 문장이 끝나면 재생 |
| 비 시작·그침, 해 짐 | 없음 | 즉시 효과 판단 → `interlude()` 즉시 요청, 5초 안에 안 오면 범용 문장 |
| 도착 | 내비 도착 이벤트, 기어 P | 결말 마무리, 효과 전부 복귀 |

### 3-4. 효과 타이밍
- 이야기 문장에 붙은 효과 태그는 그 문장을 읽기 시작할 때 실행
- 도로 이벤트에 직접 붙는 효과(예: 비 시작 → 풍량)는 이벤트 수신 즉시 실행. LLM 응답을 기다리지 않음
- 실행 전 `EffectController`가 규칙 확인: 낮인지, 공조가 켜져 있는지, 내비 안내 중인지, 상한을 넘는지

## 4. 실패와 대체

| 실패 | 대체 |
|---|---|
| API 키 없음 | `DemoStoryGenerator` (미리 만든 이야기 3편) |
| 네트워크 끊김, 응답 지연 | 범용 이음 문장 → 기본 이야기 |
| JSON 형식 오류, 안전 검사 실패, 거절 응답 | 1회 재요청 후 대체 |
| 차량 제어 실패 | 효과 없이 이야기만 진행 (로그만 남김) |
| TTS 실패 | 다음 문장으로 넘어감 |

## 5. 스레드

- Pleos SDK 콜백은 메인 스레드 기준으로 받고, LLM 호출은 `Dispatchers.IO`
- 이벤트 전달은 Kotlin `Flow<DriveEvent>`
- Director는 하나의 코루틴 스코프에서 상태를 바꿈 (동시 수정 방지)

## 6. 1차에서 하지 않는 것

- 앱 전용 화면, 주차 중 기능
- 아이 음성 입력 (STT)
- 날씨 예보, 지역 명소 같은 외부 공공 API
- 뒷좌석 전용 오디오 존, 시트 열선·통풍
