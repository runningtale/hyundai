# 고도화 제안과 결정

> 누구나 고도화 방안을 제안할 수 있습니다. 이 폴더에 제안서를 올리고, 아래 절차로 정합니다.
> 기본 방향은 `../07_고도화_계획.md`. 거기 없는 아이디어나, 거기 있는 항목을 더 구체화하는 것 모두 제안 대상입니다.

## 1. 절차

| 단계 | 누가 | 무엇을 | 기한 |
|---|---|---|---|
| 1. 제안 | 누구나 | `_template.md`를 복사해 제안서 작성 → 브랜치에 커밋 → PR | 언제든 |
| 2. 의견 | 다른 팀원 | PR에 의견 (찬성, 우려, 질문) | PR 올린 뒤 24시간 안 |
| 3. 결정 | 아래 2장 규칙 | 제안서 맨 아래 "결정"란 채우고 머지 | 의견 기한 다음 날 |
| 4. 반영 | 제안한 사람 또는 해당 묶음 | 채택이면 `07_고도화_계획.md` 표와 코드에 반영 | 결정 후 |

- 메신저에서 바로 정해도 됩니다. 그때도 제안서에 결과를 한 줄 남깁니다 (나중에 기획서와 PT 근거로 씀)
- 제안서와 PR에 실명을 쓰지 않습니다 (`CONTRIBUTING.md` 1장)

## 2. 누가 정하나

| 제안 범위 | 결정 |
|---|---|
| 한 묶음 안에서 끝나는 것 (예: 프롬프트 문구, 효과 지속 시간) | 그 묶음 담당이 결정 |
| 여러 묶음에 걸치는 것 (예: 이야기 JSON 형식 변경, 새 효과 추가) | 관련 묶음 담당 모두 합의 |
| 일정, 1차 범위, 기획 방향을 바꾸는 것 | 4명 중 3명 이상 찬성 |
| 의견이 갈려 기한 안에 못 정함 | 기획서·디자인 담당이 심사 기준(아래 3장)에 비춰 결정 |

## 3. 판단 기준

제안서마다 아래를 적고, 결정할 때도 이 순서로 봅니다.

1. **심사 기준에 도움이 되나**: 차량특화성, 창의성, 기술 활용성, 사업성 중 무엇이 좋아지나
2. **기한 안에 되나**: 1차(11/15) 전이면 P0, 아니면 P1·P2로
3. **비용**: 몇 시간, 누가, 외부 비용(API 요금 등)
4. **위험**: 안전(주행 규제, 아이 콘텐츠), 개인정보, 저작권, 다른 기능을 깨뜨릴 가능성

## 4. 마감 직전 규칙

- 11/14(토) 이후 올라온 제안은 자동으로 P1(2차 PT 준비)로 넘깁니다
- 1차 제출 전에는 "동작하는 것을 깨뜨리지 않는 제안"만 반영합니다

## 5. 파일 이름

`날짜-묶음-제목.md` (예: `20261113-story-후렴-자동삽입.md`)

- 묶음: `story`(이야기 팀), `app`(앱), `design`(기획서·디자인), `all`(전체)
